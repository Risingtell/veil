The problem

Payroll on a public chain shows every salary.

Anyone can read who was paid and how much. Mixers hide that, but they hide criminals just as well, so no bank, payroll provider or aid agency can use them. Veil follows the Privacy Pools design: payouts stay private, and each one proves it came from an approved set.

Plain mixers Unusable

  • Anyone can hide, including bad actors
  • No way to show funds are clean
  • Regulators are locked out
  • Institutions will not touch them

Veil Compliant

  • Every withdrawal proves it is in an approved set
  • No link between payer and payee on-chain
  • An auditor view key traces any payout
  • Built for payroll and aid disbursement
How it works

Three steps. The contract checks the proof itself.

The Soroban contract pays nothing unless a Groth16 proof verifies on-chain through Stellar's BN254 pairing_check host function. It also builds its own Merkle tree with the native Poseidon host function, so no operator can invent a deposit.

01 / DEPOSIT

The payer funds the pool

Each deposit adds a commitment to a tree the contract maintains, plus an encrypted record that only the auditor can open.

02 / WITHDRAW

Each person withdraws privately

A fresh wallet receives the payout with a proof that the note is real, approved and unspent, and that it pays this exact address. A relayer covers the fee.

03 / AUDIT

The auditor traces on demand

With the view key, a compliance officer opens any record and links an anonymous payout back to its deposit. The public never can.

The auditor view key

Private to the public. Open to the auditor.

At deposit, an encrypted record of identity and nullifier is published on-chain to the auditor's key, using Poseidon-ElGamal over BabyJubJub. The regulator's ability to investigate never depends on anyone keeping files.
